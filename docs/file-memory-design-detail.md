# 文件记忆与经验 Skill：实现详细稿

配套[设计主文档](file-memory-design.md)。全部为提案；主文档决定范围。
字段、命令名称和批处理大小在实现时按最小完整路径确定。
完整根目录、配置原文与任务视图见[workspace 详细稿](workspace-layout-detail.md)。

## 当前基线与替代关系

当前 `internal/state` 保存版本化记忆、证据、经验候选及 FTS5/对象索引；
`internal/host/host.go` 在执行前召回，在执行后处理沉淀。
用户陈述自动保存，经验仍需 `memory accept`。
`internal/memory/processor.go` 的 `MaxExisting = 100` 要求全量比较；
Host 超过此数量会直接报错。这是实现限制，不是 SQLite 容量限制。

新方案替代[旧 Skill 提案](experience-skills.md)中数据库权威、文件派生的关系，
并延续[经验政策](experience-memory.md)中自动发布、独立重试和禁用拦截。
既有 SQLite 查询与历史验证作为迁移和检索对比基线，不宣称旧测试证明新实现。
外部知识工具、当前事项、建议、会话历史及消息操作账本保持各自生命周期。

## 目录与内容边界

```text
.agent-host/
├── config/host.json                  # 后续加入内置 memory 设置
├── memory/
│   └── domains/<opaque-domain-id>/    # 映射现有隔离身份，不能由任意路径推导
│       ├── scope.json                # Host 配置授权的范围映射
│       ├── current.json              # 当前发布快照、各条目版本及禁用集合引用
│       ├── entries/<id>/revisions/<revision>/
│       │   ├── record.json           # 类型、时间、来源、关联、适用条件、内容摘要
│       │   └── content.md            # 事实/偏好/决策正文
│       ├── skills/<id>/revisions/<revision>/
│       │   ├── record.json           # 与知识条目使用相同的来源和身份模型
│       │   └── SKILL.md              # 标准 name/description 与方法正文
│       ├── policies/                 # 版本化禁用、恢复和纠正关系
│       └── drafts/                   # 待校验修改，不参与有效召回
├── cache/memory/                     # 可删除的检索索引
├── generated/agents/<agent-id>/workspaces/<context-id>/    # 本次任务上下文视图与原生 Skill 包
├── datasource/plugins/<plugin>/sources/<source-id>/snapshots/ # 持久来源资料
└── channels/<channel>/state/         # 现有运行数据库与来源证据
```

目录树是目标约定，不是当前已存在的运行布局。一个 domain 保留完整的
project/default scope、Agent 和 audience 约束，以及原渠道来源。
旧绝对路径 scope 作为历史身份保留，通过显式映射关联新目录，不重写证据。
同名 Agent、共同 cwd 或共享 memory 根目录都不构成授权。
知识正文不能自行修改授权；修改范围走 Host 配置与显式迁移。

正文和元数据文件、版本化策略及当前发布清单共同构成权威知识集合。
索引行、渠道数据库里的旧 memories 表、原生挂载包都不是另一套可写记忆。
运行库仍保留不可变提案、选择结果、处理 job、原始来源及发布 receipt。
文件存在不等于有效发布；读取者使用经校验的发布快照。

事实保留陈述者、观察时间、有效期、对象/主题、证据性质、替代关系与来源 locator。
Skill 保留触发描述、前提、步骤、观察到的失败方法、验证标准及来源引用。
原始日志、凭证和未经验证的助手结论不进入 Skill 正文。
Skill 默认只含指令与引用；首期不生成 scripts、hooks、工具权限或 MCP 配置。
外部引用失效时显示证据不可用，不能继续声称已核验；文件复制不保证证据可移植。
config 是运行期只读的用户输入；本流程生成的条目、元数据、策略、草案和视图
分别写入 memory、generated 或 cache，不能反向写 config。数据源原文和留存快照由所属插件管理，
新布局不另设 knowledge 根目录，旧快照的映射与显式迁移见 workspace 详细稿。

## 发布、修改与并发

复用现有工具无权限的提炼与 Jev 选择边界。Host 校验范围、证据、当前版本及禁用
集合后，发布不可变版本，再原子替换 current 清单。对比依据必须是当前快照；
发生竞争则重读并重新决策，不能用旧决策覆盖新内容。

多个渠道 worker 通过同一 Host 内部知识协调器写入；协调器持有跨进程锁，提供
发布、读取快照和恢复操作。一个 domain 在同一时刻只有一个发布者。
锁与持久化保证要用目标平台的实际文件系统验证，不能只依靠进程内 mutex。
协调器不是公共插件 API，也不统一渠道的业务状态数据库。

文件发布与运行数据库 receipt 没有跨介质事务：job 使用稳定操作 ID，记录预期
版本/内容摘要；落盘并同步版本后提交清单，最后记录 receipt 与索引检查点。
清单前中断留下未发布版本；清单后中断通过操作 ID 补 receipt 与索引。
恢复按文件发布事实判断，禁止因为 receipt 缺失重复发布或重跑业务任务。
目录同步、原子重命名和并发读取的崩溃语义列入实现验证。

用户通过 Host 查看、修改、纠正、禁用和恢复。正文可通过编辑副本进入 drafts，
Host 校验并生成新版本；修改已发布文件被发现时，该内容不再被当作有效快照，
显示校验失败并进入显式修复流程，禁止静默使用旧索引正文。
权限与范围仍由配置映射决定，文档编辑不能扩大它们。

禁用策略文件保留条目 ID、原因、来源、内容指纹、稳定关联与恢复记录。
准入先检查精确身份/指纹，再比较同范围的等价禁用候选；改变措辞不能绕过禁用。
语义等价是需评估的判定能力，不宣称所有改写都可识别；不确定时保留 proposal
与原因但不发布。到期、冲突与用户禁用分别记录，显式恢复才解除用户禁用。

## 索引、查询与适用性

首期 SQLite FTS5 是派生索引，保留现有对象、别名、主题和中英文处理作为基线。
索引键包含 domain、条目 ID、revision、正文摘要与发布代次。
长正文分段保留标题与段落定位，Skill 描述、适用条件及正文分别索引。
更新删除旧有效索引；过期和策略变更即使无正文变化也刷新可用状态。

查询流程：授权 domain → 索引候选 → 核对发布代次、摘要和有效状态 →
对象/主题/前提适用性 → 去重排序与上下文预算。相似不等于适用。
索引滞后时补齐或重建；未能恢复就报告检索不可用，禁止无声空结果或回读旧库。
任务检索与发布使用一致快照；多 domain 返回每项独立身份和版本。

自动召回延续少量事实与偏好预算。Skill 先载入相关说明，由原生引擎按需读正文；
执行中 Host 查询工具可找补充候选并读取原文与来源，所有调用复用相同范围检查。
每次检索保留 query、候选、排除理由、返回版本和实际装配记录。
说明预算、正文预算、候选数量和截断/扫描不完整状态必须可观察。

取消全量 100 条比较：提案比较使用同范围稳定对象、精确指纹、关联记录及检索
邻域，不把所有正文送入一次模型调用。身份明确的更新直接定位相关版本；
无法确定是否重复或冲突时不作覆盖。禁用筛选在独立准入阶段执行。
这种有界比较也可能漏掉等价内容，须以重复、冲突及改写测试衡量，不能把 Top-K
候选当成全域不存在重复的证明。

向量检索只在词汇基线暴露语义缺口后评估；需记录模型、版本、成本、漏召回与
误召回。外部 local-documents/Dokki/Confluence 首期沿用现有搜索读取，
不自动入学习库或与经验合并；统一外部增量索引为后续独立范围。

## 原生 Skill 装配与会话

Host 为每次调用生成私有、只含当前允许 Skill 的派生包，并记录 manifest：
domain、ID/revision、摘要、装配器版本及原生版本。包能从发布文件重新生成。
遵循既有 Agent Skills name/description 约定，具体原生加载机制先做安装版本
能力验证，再通过 `internal/harness/claude` 接入。
不写共享 `.claude/skills` 或修改用户原生配置；不通过额外工作目录扩大读取授权。
原生不支持时明确显示功能不可用，不宣称已挂载。

生成 Skill 不重复在自动上下文里放其完整步骤。调用记录区分提供、发现、加载、
实际使用及业务结果。原生引擎拥有调用与执行循环，Host 不重写其循环。
工具无权限的提炼/选择和 no-tools 请求不挂载生成 Skill。

Skill 集合或关键知识版本变化进入原生会话兼容性检查；必要时新建会话，提供
限定范围的连续上下文，排除撤回正文。启动前核对发布快照，避免已撤回内容进入
新任务；已运行任务记录旧快照，不宣称撤回可消除已执行动作或历史内容。
Codex 装配与跨引擎复用在其适配器实现后单独验证。

## 迁移、切换与回退

1. 导出每个渠道和 CLI 的 memory/revisions、关联、证据 locator、旧无效状态
   及经验候选清单。运行和 native 数据保留原位；候选仍是未发布提案。
2. 在隔离根目录生成文件集和索引，保留旧 ID/revision、scope 及来源。已接受
   方法迁移为 Skill，事实迁移为知识；缺证据或格式不支持的项保留隔离记录和原因。
   不重新推断成功、不提高历史证据强度、不自动接受 pending 候选。
3. 核对数量、状态、版本、关系和内容摘要；重放现有召回案例并比较候选差异。
   试迁移不连接平台、不启动业务任务、不写原数据库。
4. 实际切换先停止相关写入并备份，在冻结快照迁移验证后，通过 host 配置明确
   切换整个 Host 记忆后端。所有自动召回、查询/修改工具、viewer 和重试入口统一
   使用文件实现；旧 memories 表只保留历史，不做双写。重新启动并验证渠道。
5. 切换失败、尚无新知识写入时恢复配置与备份即可；有新版本后须先停止写入，
   导出新增版本、纠正与禁用记录，用回退转换器核对后恢复旧后端。
   转换器无法表达的内容必须报告并阻止有损回退，不能恢复旧备份后丢弃新内容。

首期将内置后端选择放 host 配置，不新增 `datasource.plugins.memory.json`：
它是 Host 的核心沉淀与检索功能，与外部资料提供方用途不同。
新配置缺失时保留现有后端；迁移完成后显式切换。移除旧代码后另行安排清理，
本次设计不启动迁移或改变运行配置。

## 实施与验证矩阵

| 阶段 | 主要改动 | 完成证据 |
| --- | --- | --- |
| 文件基础与迁移 | 内部知识接口、文件版本、发布协调与转换 | ID/状态/来源一致；竞争、崩溃、重复重试；切换前后可回退 |
| 索引与读取入口 | 召回、Host MCP、CLI、viewer、源引用 | 现有召回集对比；跨范围拒绝；更正与过期；索引删除重建 |
| 自动沉淀与 Skill | 提炼选择、禁用准入、Claude 装配 | 保存→新会话实际复用→纠正→禁用→改写拦截→独立恢复 |
| 实际运行切换 | 停机快照、配置、双渠道启动 | 私人事实不进群；跨渠道无隐式共享；历史可查；新版本后回退 |

增长测试先覆盖每个范围 100、1,000、10,000 项与长正文，记录查询延迟、索引重建
耗时、写入等待与实际上下文大小；目标阈值基于当前机器基线确定。
包含中文改写、英文同义词、别名、同名不同对象、否定/禁止、过期、无结果及重复
方法案例。报告相关内容是否找到、是否适用和最终任务结果，分开衡量。
初期以检索不退化、隔离零额外泄露和恢复可核对作为切换门槛；不承诺普遍收益。
每次实现运行 `make check` 与该阶段针对性验证，保留失败和 native 版本。
