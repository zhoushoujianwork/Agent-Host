# Dream 统一 HOT 与身份分区

状态：**仅设计，尚未实现。** 本文不表示当前代码、配置、生产数据或部署已经具备下述统一能力。现有 Dream 的已交付范围仍以[梦境记忆轮转](dream-memory-rotation.md)和[增量整理](dream-incremental-learning.md)为准；接口证据、兼容方案与未决风险见[详细设计](dream-unified-hot-detail.md)。

## 目标

让同一个规范 person 在不同渠道中，在明确授权下使用同一份个人 HOT，同时继续以 `person + Agent + audience + scope` 隔离记忆。渠道身份是来源和认证依据，不是唯一的数据边界；身份绑定本身不授予共享，群聊、项目和其他 Agent 的内容也不会因此串联。

## 使用方式

1. 操作者显式绑定 `channel/account/tenant/native-user` 到 canonical person；不按姓名、昵称或相似文本猜测身份。
2. 操作者为某个 `person + Agent + audience + scope` 显式挂载可共享的个人分区。只有已审核且挂载明确允许的个人偏好、个人事实或任务可以跨渠道投影；群聊和项目内容保留原 audience/scope。
3. 业务请求只从应用数据根下的固定入口读取当前 HOT：

   ```text
   <app-data-root>/dream/hot/<opaque-partition-id>/current/{MEMORY,USER,TASKS}.md
   ```

4. 本地工作台的 Dream 页面选择分区后，只读查看当前 HOT、版本来源、cycle/work/missing/cleanup 记录，并跳转到关联的 Skill 草稿。查看页面不等于允许把内容注入 Agent。

## 方案

- 分区键固定为规范 person、Agent、audience、scope。`opaque-partition-id` 由 Host 生成，只用于磁盘定位，不暴露原始渠道身份，也不替代分区元数据校验。
- 身份映射和共享挂载是两项独立决定。映射只回答“这个渠道主体是谁”；挂载另行回答“这个运行分区可以读取哪些已授权个人内容”。拒绝隐式跨 Agent、跨 audience 或跨 scope 共享。
- 每条源记录保留原 channel、account、tenant、native user、run/session 和 provenance。旧数据库不物理合并；通过可回退的只读投影适配到规范 person 分区。
- 每个分区发布不可变快照，再原子切换 `current`。失败时保留上一个已验证版本；不能就地修改快照，也不能继续加载陈旧或已撤销权限产生的投影。
- 一个逻辑协调者按分区串行共享写入，跨渠道以来源版本和策略摘要幂等，避免重复整理或双重发布。候选、冲突、审核、发布和启用继续使用现有门槛，不因统一视图而放宽。
- 映射或挂载撤销后，新加载立即失败或排除相关来源；权限代次进入运行时指纹，已有 native 会话不能继续携带撤销前上下文，必须新建兼容会话。

## 范围与边界

本设计包含身份解析、授权挂载、旧数据投影、统一 HOT 发布、撤销回收和只读 Dream 页面。它不物理迁移或合并旧 DB，不自动合并冲突，不新增通用插件 API，不增加审批写接口，不允许页面提交任意文件路径，也不改变工具、Skill、渠道或项目权限。

页面沿用现有 loopback、本地 owner 与同源动作边界。服务端只接收预配置的应用数据根和不透明分区选择；UI 能查看某分区不代表该分区已获运行时注入授权。

## 实施顺序

1. **单分区入口与只读页面：** 为一个现有精确分区生成不可变快照和原子 `current`，增加只读 Dream 页面，证明失败保留旧版本且页面不接受任意路径。
2. **显式身份与共享挂载：** 增加 canonical person 映射、独立授权挂载及跨源只读投影；证明绑定不自动共享、群聊/项目/Agent 边界不变。
3. **协调去重、撤销回收与验证：** 按分区串行写入，以来源版本和策略摘要去重；撤销映射或挂载后重建投影、轮换权限代次并拒绝继续旧 native 会话。

每阶段都应可单独关闭并回到现有按渠道数据读取方式；没有完成隔离、回退和撤销验证前，不进入下一阶段或生产启用。
