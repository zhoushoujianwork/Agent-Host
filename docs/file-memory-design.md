# 文件记忆与经验 Skill

状态：2026-10-13 本期已实现并完成本地迁移，历史数据对照、缓存重建、
回退及真实 Claude Skill 调用已通过。实现细节与验证范围见[详细稿](file-memory-design-detail.md)，
目录与角色文件见[workspace 约定](workspace-layout.md)。

## 使用方式

用户照常提交任务。Host 保存有依据的事实和处理方法，下次任务先检索适用内容，
再交给 Claude Code 使用。事实、偏好与决策保存为文档；处理方法保存为 Skill。
执行记录与原始证据继续保留，学习不会改写用户的配置。

当前可以查看、禁用和显式恢复记忆。已发布文件受摘要校验保护；直接编辑文件
会触发错误，不会自动导入新正文。编辑副本、校验并发布新版本的工作流尚未交付。

## 保存位置与职责

| 内容 | 位置与职责 |
| --- | --- |
| 正式事实、偏好、决策 | `memory/domains/<domain-id>/entries/`，保存正文、来源和版本 |
| 正式处理方法 | `memory/domains/<domain-id>/skills/`，保存 `SKILL.md` 与版本 |
| 当前发布状态 | `memory/sources/<source-key>/current.json`，决定哪些版本正式生效 |
| 检索索引 | `cache/memory/`，SQLite 可从正式记忆文件重建 |
| 本次任务上下文与原生 Skill 包 | `cache/workspaces/<run-id>/`，可重建任务副本 |
| 运行、会话与证据 | 渠道或 CLI 状态数据库，属于正式运行记录 |
| 用户维护的角色与偏好 | `config/agents/`、`config/users/`，运行期只读 |
| 外部资料 | 数据源配置引用的原文及所属插件的持久快照 |

**正式记忆是文件，SQLite 记忆索引是缓存。** 删除缓存能够重建；正式记忆和运行
记录都需要备份。不同渠道、Agent、项目和群聊仍保留各自范围，不因目录共享而合并。

## 沉淀与召回

用户陈述经 Jev 选择后自动保存。文件后端中的执行经验经独立提炼、证据检查、
Jev 比较和 Host 校验后自动发布，正常流程无需逐条 `memory accept`。
旧 SQLite 后端继续保留原来的人工接受流程，历史候选不会因迁移被自动接受。

检索采用现有中英文全文、对象、别名和主题匹配，并核对生效版本、有效期与
适用条件。当前最多装配 8 项记忆、12 KiB 记忆正文；有界比较替代全量比较，
单个范围积累超过 100 条不再因此阻止任务执行。禁用内容参与准入检查但不参与召回。

Claude 按任务收到仅含适用处理方法的私有 Skill 包。包中保留来源和条件，
不生成脚本、不授予工具；更新或禁用影响后续任务的会话选择。

## 启用与迁移

先停止写入并备份，再对每个渠道状态目录执行 `memory migrate`，使用不同来源名；
通过 `memory verify` 核对后，把 `host.json` 的 `memory.backend` 设为 `files`，
检查配置并重新启动。详细命令见[迁移说明](file-memory-design-detail.md#迁移命令与回退)。

`memory rollback` 会把文件期间的新版本、纠正和禁用记录一起转换回 SQLite，
核对后才退出文件后端。运行期不双写旧记忆表，也不通过恢复旧备份丢弃新知识。

## 验证与后续范围

历史钉钉的 3 条记忆、6 个版本、3 个证据关联，以及飞书空记忆库已通过隔离试迁移、
检索对照、缓存删除重建和回退。真实 Claude 已发现并成功调用一个历史 Skill，
仅总结已有来源，未执行业务操作；这不代表一般任务收益已经测量。

直接编辑记忆的导入与草稿流程、手写 `config/skills` 的新挂载入口、向量检索、
多万条性能、Codex Skill 适配和外部资料统一增量索引仍未交付。
