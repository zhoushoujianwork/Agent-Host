# Dream 增量整理与 Skill 演进

状态：已实现并通过本地 `make check`；本次变更尚未部署。Dream 按可信分区增量检查 Host 执行记录，保存唤醒账本；有依据的 Skill 改进进入新版本草稿，过期派生缓存按保留期清理。实现细节见[详细稿](dream-incremental-learning-detail.md)，现有能力见[梦境记忆轮转](dream-memory-rotation.md)。

## 目标

Dream 在宿主空闲时整理会话与执行证据，记住上次处理到哪里、得出了什么结论、还缺什么。下次醒来只重新评估新增或发生变化的内容，而不是重新阅读全部历史、重复生成记忆或技能。

## 一轮整理做什么

1. 读取新的执行记录，以及证据、验收结果或依赖版本已变化的旧记录。
2. 对照会话上下文、最终结果和实际 Skill 使用情况，区分“提供了 Skill”“读取了 Skill”和“执行结果支持改进”。读取 Skill 本身不能证明操作成功。
3. 保存本轮结论、缺失证据、下一次重评条件及产物引用。证据不变的已处理内容不重复调用模型。
4. 把有依据的改进映射为已有托管 Skill 的新版本草稿；没有合适目标时新建 Skill 草稿。草稿不改变当前启用版本。
5. 将过期候选标为已过期，沿用现有 HOT 记忆归档，并清理超过保留期的派生缓存。

## 生效与清理边界

- HOT 和 Skill 都要经过评估。自动生效策略另行配置；本期沿用现有审核、发布和启用规则，不能把生成草稿表述为已经启用。
- `draft_skills` 默认关闭；启用后，后台只自动创建待审核草稿。
- Dream 更新托管 Skill 的版本，不直接改写全局技能源目录，不自行扩大工具权限或适用人群。
- 缓存可以按保留策略物理删除；原始交接文档、会话事件、权威记忆、Skill 历史版本和审核记录不随缓存一起删除。
- 正在使用、归属不明、内容已被外部改动或存在依赖的文件不删除。删除先记意图，完成后记结果；中断后可以核对和继续。

## 查看结果

每条整理记录应能查看：关联会话和执行、使用的 Skill 版本、上次证据版本、处理结论、还缺的证据、生成或修订的产物，以及为何再次处理或跳过。当前通过条目账本和周期状态查询；尚无按这些类别汇总的可视化面板。

提供 `dream work-list` 与 `dream work-show`，要求精确 person/Agent/audience/scope。它们显示当前与前次证据 digest、run/session、缺失原因、重试状态、候选/收据引用，以及“提供”“实际加载”“引用读取”分开的 Skill 证据。候选记录保存 Skill 目标版本和实际生成版本；`dream cleanup-list` 显示清理意图与完成记录。

## 实施顺序

先实现会话证据采集与持久检查点，修复证据补齐后无法重评的问题；再接入 Skill 新版本草稿和有淘汰记录的缓存清理。最后以重启恢复、同内容不重复提炼、证据变化重评和删除边界测试验收。
