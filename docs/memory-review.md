# 候选记忆的有界审查

已实现只读 JSON 报告，默认列出超过七天的最老 20 条待审候选：

```sh
agent-host memory review-report --home /absolute/runtime/channels/dingtalk/state
agent-host memory review-report --home /absolute/runtime/channels/dingtalk/state --min-age 0h --status all --limit 20
```

报告提供年龄、脱敏范围/分区指纹、来源运行 ID、证据数量、审查状态与备注是否存在。
年龄只是排队依据，不代表持久化错误；接受候选、提炼完成和正式发布分别判断。
报告不接受、发布、删除候选，也不重放、修复、启动或重启运行时。
[详细契约与限制](memory-review-detail.md)。

## 操作路径与负责人

1. 运行时维护者负责生成报告和分派审查；由有权访问对应范围的项目/知识负责人作内容决定。
   当前存储没有候选负责人字段，必须在私有操作记录中指定实际负责人，不能从发送者身份推断授权。
2. 每批最多 20 条、最多 30 分钟。先看最老的 pending；达到任一上限就停止并记录是否仍有剩余项及下一次复查日期。
   `truncated=true` 表示仍有匹配项；不能把这一批视为完整清单。
3. 在已授权的私有证据界面按候选 ID、来源运行 ID 核对原证据、当前发布版本、后续候选和审查记录。
   不将正文或私人身份复制到共享报告。先确认是否被后续内容取代、是否有意暂缓；不能仅凭时间较新决定取代。
4. 每条记录负责人、决定（继续暂缓/已取代/需要进一步核验/另行授权处理）、证据引用、理由与复查日期。
   缺少证据或负责人则保持原状。当前候选只有 pending/accepted/rejected；“已取代”是需引用证据的人工结论，
   不新增或伪造候选状态，也不从自由文本备注自动推断。
5. 修改候选或发布需单独明确授权，并核对当前后端适用的既有流程。旧 SQLite 人工接受与文件后端自动发布
   不可混用。此报告和审查步骤本身不触发这些操作。

暂缓原因或处置决定；这些决定由实际范围负责人在上述有界审查中完成。
