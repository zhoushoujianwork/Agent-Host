# 梦境记忆轮转

状态：设计提案，尚未实现。本文只定义目标、使用方式和产品边界；拟议的数据结构、
接口、恢复协议与验证矩阵见[详细稿](dream-memory-rotation-detail.md)。现有架构、
[文件记忆](file-memory-design.md)、[执行经验](experience-memory.md)和
[托管 Skills](managed-skills-design.md)仍是已交付行为的依据。

## 目标与使用方式

Agent-Host（agh）在业务任务之外，对已定稿的原始交接执行记录做一次离线“梦境”整理：
保存不可变来源，选出有证据、范围明确且不过度推断的知识，先进入有有效期的热记忆；
可复用方法再成为 Skill 候选，经现有审核、发布和显式启用后供后续任务使用。

第一期只提供 Host 拥有的离线单次 worker。操作者指定私有来源、目标 Agent/audience/scope、
预算和策略版本，先预览再执行。后续才可在明确启用后，由 Host 单写者服务队列定时触发；
不新增独立守护进程、第二套记忆真相库或通用插件加载器。

## 所有权与边界

| 组件 | 职责 |
| --- | --- |
| Host | 来源准入、范围、策略、队列、租约、预算、状态、发布、停用与恢复 |
| Offload Go package | 启动有界提炼；使用隔离的干净 Agent，不提供业务工具或操作权限 |
| 原生引擎 | 在一次提炼调用内完成模型循环和结构化输出，不拥有记忆生命周期 |
| 文件记忆与 Skill 目录 | 保存正式版本；现有索引仍是可重建缓存 |

原始证据与派生知识始终分离。来源文本、Agent 报告、退出码或“完成”字样不能授予权限，
也不能单独证明业务验收。执行完成、业务接受、记忆准入、Skill 审核与启用是不同结果。

## 范围

第一期包含：已定稿交接目录扫描、稳定摘要、幂等检查点、规范 Run 优先取证、离线候选提炼、
热记忆 TTL、待审 Skill 候选、显式退役/恢复、失败恢复和只读诊断。

第一期不包含：物理删除、自动合并多个方法、全局用户偏好推断、自动工具授权、自动启用 Skill、
业务任务重放、网络资料补全、生产调度默认开启、无界历史回填或一般质量收益承诺。

## 生命周期

```text
原始记录（不可变、独立保留）
  → 已发现 → 已校验 → 已提炼
  → 热记忆候选 → 热记忆（有范围、TTL）
  → Skill 候选 → 已审核 → 已发布 → 显式启用
  → 冷停用/归档 → 显式恢复
```

1. **发现与定稿。** 只接收 `exit_code != null`、完整稳定摘要清单且未发生符号链接逃逸的目录。
   文件在两次读取间变化则失败；不把未知退出解释为失败或成功。
2. **取证与提炼。** 能解析到现有规范 Run 时，优先引用原 Run 与成对工具事件；孤立记录保留
   `external_agent_supplied` 归属。报告和请求可作上下文，不能代替工具结果。
3. **热记忆。** 仅策略允许、有支持、无冲突且范围明确的知识可自动进入 TTL 热层；其余保持
   `pending_review`。热层是正式记忆的有界检索视图，不是另一套真相数据库。
4. **Skill 晋升。** 不是每条事实都成为 Skill。只有可复用程序形成候选，并沿用现有
   review → publish → enable 流程；晋升绝不自动增加工具、插件或原生 Skill allowlist。
5. **轮转与退役。** TTL 到期立即排除召回。冷停用/归档保留版本、来源、决策与恢复路径；
   首版不物理删除。未来删除必须服从保留策略，并先保护仍被记忆、Skill 或审计引用的证据。

## 准入决策

| 观察 | 决策 |
| --- | --- |
| 策略允许、证据支持、无冲突、范围明确 | 可自动进入有 TTL 的 scoped hot memory |
| 支持不足、关系不确定、冲突或需要负责人判断 | `pending_review`，不得进入主动召回 |
| Agent 报告 `BLOCKED`、候选被拒、执行失败或结果未知 | 仅诊断；不得生成正向成功程序 |
| 明确失败证据形成可复用避坑经验 | 可作为负向候选，但必须保留失败语义与适用条件 |
| 用户偏好只在某次交接中出现 | 不推断为全局偏好；需要已认证用户陈述与明确范围 |

人工决定与显式策略决定必须分别记录真实 actor、策略版本、理由和证据；模型选择不得伪装成人审。

## 交付顺序与停止条件

1. 先交付只读扫描/预览及固定夹具，证明来源稳定、幂等键和零记忆写入。
2. 再交付手动单次 worker，只写热记忆候选和诊断；证明崩溃恢复且不重放业务任务。
3. 再接现有 Skill 审核/发布，不自动启用；证明 allowlist 和工具权限不变。
4. 最后才提供默认关闭的后台调度，复用 Host 单写者队列、租约和暂停/取消。

任一阶段若不能证明来源未变、范围唯一、发布幂等或失败可恢复，就停在只读/待审状态。

## 当前可行性与限制

现有隔离测试已通过 `internal/state`、`internal/experience`、`internal/managedskills`、
`internal/assembly`、`internal/host`；交接导出器 37 个 Python 测试通过。它们证明可复用的
收据、证据筛选、版本和 Skill 生命周期基础，不是本设计的端到端验收。

干净 Agent 的强制禁用工具能力仍须按所选 backend 做独立探针，不支持时停止该阶段。

当前没有原始交接扫描器、通用梦境调度器或自动方法合并器，也没有梦境提炼质量、生产延迟、
成本或长期召回收益的端到端证据。详细的拟议协议、时间线和隔离验收见
[详细稿](dream-memory-rotation-detail.md)。
