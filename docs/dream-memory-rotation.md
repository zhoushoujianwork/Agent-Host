# 梦境记忆轮转

状态：首版已实现，生产默认关闭；新提炼结果先待审，尚未实现策略自动准入。
实现协议与验收记录见[详细稿](dream-memory-rotation-detail.md)。

## 目标与产物

AGH 在空闲后台整理已定稿的历史执行记录，逐步积累每个人的工作偏好、常用方法和当前任务。
这些内容用于组装符合本人工作方式的 Agent 上下文；首版不自动创建新的 Agent 实例，也不从一次行为推断心理人设。

主要产物分三层：

| 产物 | 用途与边界 |
| --- | --- |
| HOT 记忆 | `USER.md` 保存经确认的工作偏好，`MEMORY.md` 保存有来源的事实和经验，`TASKS.md` 保存当前任务；都有范围和有效期 |
| Skill 草稿 | 可复用方法进入既有审核、发布、显式启用流程；不会自动获得工具权限 |
| 归档 | 到期或停用后退出召回，保留原始记录、版本和来源，等待后续保留策略决定淘汰；首版不物理删除 |

HOT 按本人、Agent、会话受众和记忆范围隔离。私聊使用本人的内容，群聊不注入个人 HOT。
`AGENTS.md`、`SECURITY.md` 仍由操作者维护，不由历史记录生成或覆盖。

## 使用方式

1. 对应用数据目录中的原始交接记录执行 `dream scan`，只读检查来源是否完整、稳定。
2. 用 `dream run` 提炼待审候选，查看来源并通过 `dream review` 接受或拒绝。
3. 接受后的记忆进入现有版本化存储；显式配置 `--dream-config` 后，私聊与 CLI Chat 加载 HOT 快照。
4. 启用后台周期后，AGH 只在所有配置状态目录持续空闲达到 quiet window 后提炼；前台到达会取消本轮模型调用，稍后重新准入。周期结果可查询，失败不会伪装为成功。

数据放在应用数据目录，配置文件只保存开关与路径。HOT 文件是可重建的快照，正式记忆和 Skill 版本才是权威来源。
记忆到期或变更后，旧原生会话需要重新开始，避免旧上下文继续保留已失效内容。

## 与 Offload 的分工

AGH 负责扫描、身份范围、审核、记忆轮转和后台周期；Offload Go package 只负责执行隔离的模型调用，
以及把选定文档传给业务 Agent。不会把梦境机制交给 Offload 的任务调度器。

运行时将 `USER.md` 映射为 Offload 支持的 `USERS.md`，将 `TASKS.md` 作为标记小节并入 `MEMORY.md`。
业务执行继续使用已配置模型；严格无工具的梦境提炼目前只支持 Claude，其他提炼后端会明确拒绝，不自动切换。

## 本期边界

已实现来源扫描、幂等提炼、候选审核、HOT 导出与私聊注入、后台周期、Skill 草稿晋升、到期归档及显式恢复。
新候选全部先待审；没有自动审核、自动启用 Skill、自动扩权、业务任务重放或无界历史回填。

运行时已接入直接 Offload 与 Full Host 的 CLI Chat、私聊渠道和 room 路径。Full Host 保留原有 Agent catalog、
Skill、插件与记忆组装；只有认证本人且 Agent、audience、scope 精确匹配时才注入个人 HOT，群聊和其他人保持原行为。
每个前台请求先冻结一次 HOT，摘要和文档共同绑定会话与派发；期间发布的新摘要只影响下一请求。
HOT 摘要变化会拒绝继续旧会话，要求新建会话。CLI Chat 仅支持 HOT，不拥有后台写入生命周期。

Skill 目录目前不能表达任意个人权限，因此首版仅允许本地 owner 的方法晋升为草稿；其他个人的方法保留为候选。
后续可在验证实际整理质量后，再增加明确的自动准入策略和个人 Skill 权限，不以模型输出替代审核。
